# 04 — Detect gestures from window geometry, like legacy

## Scope

Native check of parts 01–03 (2026-11-26, release install): drag and resize still fail for most windows (Ghostty, Device Hub; Finder worked once), and a resize snaps back **while the button is still held**. Live status after many attempts: `gestures: 2, ignored: 0, cancelled: 0`, `available: true`. Most mouse downs never reach the actor, so no gesture exists and the planner fights the user live. `available` only reports that the subscription succeeded at start, not that the shared listen-only tap still delivers.

Legacy (`_legacy/app/native/src/modules/tiling/events/mouse_monitor.rs`, `drag_state.rs`, `actor/handlers/window.rs::on_batched_geometry_updates`, removed in `8c70e93d`, read with `git show 8c70e93d^:<path>`) did not depend on seeing the down: its own listen-only HID tap also observed `*MouseDragged` (which sets "mouse down" even when the down was missed), and the operation started at the **first window geometry update while a button was down**, snapshotting the moved window's workspace. Relayouts were frozen while it lasted; the mouse up finished it.

## Requirements

1. **Gesture start from geometry.** A move or resize observation (AX notification, window-server geometry, or a snapshot reply) of a tiled window on a visible workspace, while a mouse button is physically held, starts a gesture if none exists, capturing that window's workspace with every tile's baseline frame: the last frame the planner wrote/confirmed (desired or settled actual), never the frame the user has already changed. The down signal remains an earlier start when it arrives (current behaviour, display under the pointer).
2. **Button state without the tap.** "Held" is read from `CGEventSourceButtonState(kCGEventSourceStateCombinedSessionState, button)` for left and right buttons (no permission needed), behind a small injectable trait so tests drive it. Add the binding in `stache-macos` if absent.
3. **Gesture end without the tap.** The gesture ends on the tap's up as today, or, if the tap misses it, when the button-state check reports no button held. While (and only while) a gesture is active, the actor checks button state on each geometry observation and on a bounded timer (about 50 ms), so a missed up ends the gesture within about 100 ms. No timer runs when no gesture is active. The 60 s timeout stays as the last resort.
4. **Never fight a held button.** `plan_and_issue` writes nothing to a workspace with an active gesture; and before issuing an external-change correction for a window whose frame changed outside our writes, if a button is held, a gesture is started instead of the write.
5. **Commit unchanged:** swap, snap-back and the part 02 edge-aware resize run as today on the captured baselines and the fresh reads.
6. **Tap health in status.** The drag status section reports the live tap state from the input service (`TapStatus`: ready, disabled, re-enable failed with attempts), how many downs/ups the observer delivered, lost observations, and how many gestures started from geometry vs from a down. `available` reflects the live state, not only the start.
7. Investigate why the shared tap misses downs (owner thread park/mode, tap disabled by timeout and the 3-attempt re-enable budget, router contention), and fix it if the cause is found and the fix is contained to the input service; record findings in Notes. The geometry path must work even with the tap entirely dead.

## Acceptance criteria

- [x] End-to-end scenario, tap delivering **no** mouse events at all: user drags a Grid tile (button held per the fake button state, streamed geometry notifications) → no write while held; on release (button state up) the tile snaps back / swaps; a resize relays out neighbours.
- [x] Scenario: resize held for 2 s with notifications every 16 ms → zero frame writes to that workspace until release.
- [x] Scenario: tap delivers the down but misses the up → gesture ends within about 100 ms of the button-state release.
- [x] Scenario: Ghostty-like window (split_horizontal with two apps, like the live `terminal` workspace with Ghostty and Device Hub) resized by the user → keeps the new size, neighbour adjusts.
- [x] No timer wakes while no gesture is active (asserted).
- [x] Status shows live tap state and the new counters (table and JSON), docs updated (`docs/features/tiling.md` Passive drag; `docs/architecture/ipc.md`).

## Notes

Tap investigation (2026-11-26, code reading; no native run):

- **Found: one slow callback silenced the observer for the rest of the run.** `Router::invoke_observer` (`src/crates/sdk/src/input/router.rs`) marked a passive observer inert (`InertReason::Slow`) on its _first_ callback over `CALLBACK_SOFT_TARGET` (1 ms, wall time measured around the call). Tiling's `DragObserver` calls `Ingress::submit`, which takes the actor mailbox lock that the actor also holds while admitting a whole sink batch, so one contended lock, a page fault or one preemption of the `stache-input-owner` thread was enough. From then on `dispatch_passive` skipped the entry silently: no down, no up, no discontinuity, nothing in Tiling's status, while the tap itself stayed `Ready` (hence `available: true`, `ignored 0`, `cancelled 0`). This matches the live capture (two gestures, then nothing). Fix, contained to the input service: a passive observer becomes inert only after `OBSERVER_SLOW_STREAK` (8) consecutive slow callbacks; a callback within the target resets the streak; every slow callback is still counted. Handlers keep the first-slow-callback rule (they hold up input). Test: `a_slow_passive_callback_is_counted_but_only_a_streak_inerts_the_observer` (sdk; fails on the old rule at the first assertion).
- Not the cause, by reading: the owner thread parks in `CFRunLoopRunInMode(default, PARK_LIMIT, returnAfterSourceHandled)` in a loop, and the tap's run-loop source is in the same default mode, so events queue in the mach port while it processes control requests; a listen-only tap disabled by timeout is reported as a discontinuity (it would have shown as `cancelled`/`lost`), and `MAX_RETRY_ATTEMPTS = 3` bounds only explicit `retry_reenable` calls, not the automatic re-enable after a disable. `load_nonblocking` contention drops only while a writer republishes the subscriber set (subscribe/unsubscribe), which is rare.
- Status now shows the observer's live health: `tap` is `observer inert (Slow)` when the service made the observer inert, else the `TapStatus` of the listen-only tap, and `available` is false whenever it delivers nothing.

Implementation:

- Gestures start from geometry (`state/drag.rs::observe`, called from `Moved`/`Resized` notifications, from snapshot events, snapshot and window-server reads before the frame is stored, and from our own write's readback in `frames::complete` before it is stored) when the actor's `ButtonState` reports a held button. In production `Moved`/`Resized` reach the actor as a geometry batch that issues a `ReadGeometry` (write in flight) or a `Snapshot`, so the reads and the write readbacks are the real triggers. A frame our in-flight write explains (`frames::explained_by_travel` from its start to its target), or a late settle echo on the finished animation's path, starts nothing; a frame off that path starts the gesture with the write's target as the moved window's baseline, and that readback then sets no `size_check`, infers no minimum and moves no baseline. A read whose frame is near the baseline starts nothing (a click or refresh while a button is held).
- Baselines (review fix): every captured window starts at its latest observed frame (a down-started gesture always did); the moved window of a geometry-started gesture uses its frame before the observation (our settled frame when still within the tolerance of it, since sub-tolerance reads are stored as they come), or its in-flight write's target. The planner's record is no longer used for siblings: an unconfirmed target, a refused minimum, a terminal grid or a mid-animation sibling made a drop read as a sibling resize. Siblings whose animation `begin` cancels (`DragWindow::settling`; not the moved window, nor at a down the window under the press) may stop anywhere on their way, so they are excluded from the resized/dragged selection and stay drop targets (chosen over re-reading them: simplest and deterministic). A readback off its write's path never rebases during a gesture.
- `begin` cancels every in-flight or queued write of the captured windows, animated or direct, plus every running animation. `FrameControl` now keeps the issuance of each direct write handed to a shard, so the cancel reaches a write already waiting in the application's AX queue.
- The observer hands signals to `Ingress::submit_drag`, which try-locks the mailbox and otherwise stages the signal (32 entries, overflow is one `Lost(Overflow)`); the next lock holder admits staged signals first. Review fix: the actor flushes the stage after every wake and checks it under the mailbox lock right before sleeping (marking itself asleep); a signal staged while it is asleep or about to sleep is admitted by the callback itself once the short lock holder releases (`try_lock` with `yield_now`, never while the actor works), and every lock holder that flushes a stage notifies, so no wakeup is lost (`a_staged_drag_signal_wakes_the_sleeping_actor`).
- A gesture the tap's down started gets one `RELEASE_POLL` before the button state may end it, so a quick click's own up ends it and `released_by_state` counts only missed ups.
- Release without the tap: `DragSignal::Released`, sent by `Engine::watch_gesture` when the button state shows no button held; it polls every `RELEASE_POLL` (50 ms) only while a gesture waits for its up. A geometry observation with no button held ends it too.
- Production composes `stache_tiling::SystemButtons` (`TilingParts::buttons`, host `production`) over `stache_macos::input::mouse_button_held` (`CGEventSourceButtonState`, combined session state; objc2-core-graphics `CGEventSource` feature). Tests and other rigs run without a button source (gestures then start only at a down, as before).
- Planning was already suppressed globally while any gesture exists; requirement 4's "start a gesture instead of the correction" is met because the observation that would cause the correction starts the gesture first, in the same transition, before the plan.
- Review fixes (part 04 second pass): a readback of our own write starts a gesture only when its position is off the write's path; a size-only difference on the path (a minimum, a terminal grid) is a refusal, even with a button held (`a_held_button_and_a_size_snapped_readback_of_our_write_start_no_gesture`). The window under a down's press is never `settling`: the press is tested against its observed frame and the bounding box of its in-flight animation's start and target (`a_window_grabbed_mid_animation_outside_its_lagging_frame_is_the_users`). The off-path suppression of size checks, inference and rebase applies only to windows the gesture captured (`a_gesture_does_not_suppress_minimum_inference_of_uncaptured_windows`). Known limit: the quick-click grace is actor-time based (`Engine::watch_gesture`), so `observe` ends a tap-started gesture on the first geometry observation that shows no button held, without the grace.
