# 02 — Owned runtime and read-only status

Read when checking the completed Keep Awake runtime and read-only status contract. This part ships on `main`; requirements and acceptance evidence are retained below.

## Scope

Implement `KeepAwakeModule`, policy tests, runtime DTOs and a published snapshot reader in `src/crates/modules/keep-awake/src/` (suggested `runtime.rs`, `status.rs`). The app owns the top-level `KeepAwakeStatus` envelope and `IpcHandler` because `ModuleStatusView` is app-owned. Wire them with the production factory in `src/crates/app/src/host.rs`, DTO export in `bindings.rs`, required app dependencies and host integration tests. Reuse part 01 adapters; native fixes stay in `stache-macos`.

The app owns generic factory/registry/router composition; the module owns power policy. No module-specific SDK branch, module-to-app dependency, private config mirror, second control/config store or Bar/noTunes dependency. Only small generic factory context plumbing is allowed as needed for main-thread ownership, published lifecycle reads or held store diagnostics; follow the overview's merge/reuse integration rule. Keep the existing proxyAudio factory working unchanged in behavior.

## Requirements

### Lifecycle and reconciliation

1. Descriptor ID is `keepAwake`; requires/provides/permissions/executables/surfaces are empty. Construction and `configure` acquire nothing. Register through `host::register_module` so initial-invalid registration, config binding and recovery remain generic.
2. `start` installs observation (or records fallback), probes current lock state **before** any acquisition, then establishes one generation/worker and one owned timer. Apply part 01's mapping: valid dictionary/key absent is compatibility-unlocked, not a failed probe; explicit booleans map locked/unlocked; null/unreadable dictionary or present non-boolean is unknown. Known locked startup succeeds as `Running`, with no assertion. Initial required probe/unknown or acquisition failure returns typed `ModuleError` for `Operation::Start`/platform category and attempts full rollback; unresolved rollback retains pending ownership and status rather than claiming inactivity. Generic Retry/resume first resolves pending cleanup before any fresh acquisition. Observer failure alone may succeed degraded when the probe works.
3. While active, refresh on coalesced notification hints and at most two seconds between scheduled reconciliation attempts. Use a cancellation-wakeable wait, not busy polling, detached sleep loops or a timer per notification. Notifications can drop or lie: probe current lock state, never replay a diff payload as authority.
4. Known unlocked + enabled/unpaused/live generation requests one all-three assertion lease only when no prior IDs remain unresolved. Publish `acquiring` before native creation/candidate-validation work and retain it until complete adoption or cleanup begins. Known locked attempts release. Unknown/probe failure suppresses acquisition and attempts release of any held lease. Publish `releasePending` before the first native release/rollback call, including normal cleanup; retain it while cleanup is in progress or failed/unresolved, with IDs owned and no replacement lease until resolved. Normal transitions alone do not set `assertionReleaseFailed`. A later successful probe recovers automatically only subject to that cleanup gate; unlock while paused/disabled is inert. Resume installs/probes anew before acquisition, never trusts stale unlocked knowledge.
5. Use SDK-owned named workers and cancellation token. The registry cancels before `Module::stop`, then joins. Stop invalidates the generation first, wakes the worker, unregisters observation and explicitly releases the lease; repeated cleanup is safe after partial start/spawn failure. Release failure during stop/pause/disable returns the existing lifecycle cleanup error and retains pending IDs plus `assertionReleaseFailed`; never reset assertion state to inactive merely because Stop ran. Pause/disable leave no acquisition work, timer or effective callback running, but may retain inert owned cleanup state. Retry cleanup through bounded owned reconciliation while active or the next lifecycle cleanup, not a detached reaper or busy loop. Cleanup deadlines obey part 01; delayed native removal remains inert and safely owned, not falsely reported completed. Final Drop is best-effort, not a successful release acknowledgement; process-exit OS release is the ultimate boundary, not proof that application cleanup succeeded.
6. Guard acquisition adoption by generation and refresh identity: cancellation, observed lock/unknown state or a newer lock refresh wins over an in-flight candidate. Recheck current lock snapshot after a racing acquisition before publishing/adopting it; complete valid adoption changes `acquiring` to `active`. Cancelled/stale candidates change to `releasePending` before immediate explicit rollback and remain there until cleanup is confirmed; actual rollback failure also sets `assertionReleaseFailed`. Normal release likewise becomes `inactive` only after confirmed cleanup, with no outstanding work, candidate or unresolved IDs. Pending IDs retain their original owner identity; block newly attempted generations from acquiring until they resolve. Old notifications, queued installs/removals, worker completions and cleanup cannot mutate/release a successor's IDs. No transient candidate is published as active or falsely claimed confirmed released.
7. No state/published-snapshot mutex is held across probing, acquisition/release, dispatcher waits or worker joins. Stage native work outside short locks, then validate/adopt by identity. This does **not** require the registry to release its existing per-slot lifecycle/module lock across `Module` methods; published reads must avoid that lock and remain prompt during transitions.
8. Repeated starts, unchanged typed config, equivalent reload bytes and watcher echo after tray edits create no duplicate lease/observer/worker/timer. With `enabled` as the only field, enabled-to-enabled reconfigure does not restart resources. Disable/pause/reload semantics stay SDK-owned; malformed initial config stays revision 0/inactive, and malformed reload retains the accepted runtime plus a separate diagnostic.

### Failures

9. Runtime probe failure sets lock unknown, attempts release and publishes a typed actionable condition. Runtime acquisition failure leaves `inactive` only if rollback confirms all owned IDs released; publish `releasePending` while rollback is in progress or unresolved, adding `assertionReleaseFailed` only on actual rollback failure. Retry only on scheduled reconciliation/explicit lifecycle cleanup or resume, not a tight loop. Deduplicate unchanged conditions in logs; publish/log recovery when the condition changes. An observation warning may coexist with probe/acquire/release errors. Observer fallback may persist for that generation; the next lifecycle start/resume retries subscription, clearing its warning only after successful installation. No recurring observer-reinstallation service is required.
10. Runtime degradation need not change SDK `Running`: it describes resource lifecycle, not successful power prevention. Do not invent a nonexistent SDK `report_failure` callback. Start/stop failures use existing lifecycle errors; live failures are in Keep Awake status. File/config diagnostics remain separate. Native cleanup failure is not concealed as successful cleanup.

### Concrete status contract

11. Contribute only `keepAwake.status` on the existing socket router. Empty/omitted/null params mean the same zero-argument request; reject nonempty/ill-typed params via typed decoding. Unknown methods return `unknownMethod`. Disabled, paused, initially invalid, locked and failed modules still answer status successfully; query availability must not be gated on `Running`.
12. Export Rust serde/Specta DTOs, camelCase on the wire, from the same collection as the shipped bindings (no Tauri command or hand-written TS mirror):

| Type/field                                    | Planned meaning                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| --------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `KeepAwakeStatus.module`                      | App `ModuleStatusView` projection of published SDK `ModuleSnapshot`: lifecycle, enabled, paused, exact revision string; diagnostic overlays the held `ConfigStore::diagnostic` first, then registry lifecycle/validation diagnostic. No config duplication in runtime DTO.                                                                                                                                                                                                                                                                                                          |
| `KeepAwakeStatus.runtime`                     | `KeepAwakeRuntimeStatus`, the module's single published runtime observation.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `runtime.assertionState: AssertionState`      | Typed `inactive` (release confirmed; no outstanding acquisition, candidate or unresolved IDs), `acquiring` (published before native creation/candidate validation; unadopted work in flight), `active` (current generation's complete adopted all-three lease), or `releasePending` (published before native release/rollback; cleanup in progress or failed/unresolved, so sleep may still be prevented). Never inferred from lifecycle/enabled.                                                                                                                                   |
| `runtime.lockState: LockState`                | `unknown`, `locked`, `unlocked`; inactive runtime resets to unknown rather than presenting an old observation as current.                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `runtime.observation: LockObservation`        | `inactive`, `notificationsAndPolling`, `pollingFallback`; registration success does not guarantee event delivery.                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `runtime.conditions: Vec<KeepAwakeCondition>` | Current deduplicated conditions, stable order; empty when healthy. Each has typed `kind` and actionable `message`. Kinds: `observerUnavailable`, `lockProbeFailed`, `assertionAcquireFailed`, `assertionReleaseFailed`, `observationDispatchFailed`. Set release failure only after actual release/rollback failure, not normal acquiring/releasePending transitions; include actionable cleanup uncertainty and retain it even paused/disabled/failed until pending IDs resolve. Clean stop clears it only after confirmed release. Other conditions clear on recovery/clean stop. |

13. The module publishes runtime observations under a short separate lock. The app-owned `IpcHandler` mechanically decodes requests and composes the app-owned `KeepAwakeStatus` at the wire boundary from the module snapshot reader, published registry metadata and held file diagnostic, never a module lock or power policy. `ModuleSnapshot` lacks serde/Specta: reuse its app projection, not a new wire mirror. `ModuleStatusView::from_snapshot` currently copies only snapshot diagnostics; explicitly overlay held `ConfigStore::diagnostic` using file-first, registry-second precedence. Parse/type/I/O/deletion rejection can occur before Registry and must remain visible without changing the last-good lease, accepted config/revision or runtime. Repair with identical last-good bytes clears both store and snapshot diagnostics. Pass only narrow read-only sources through generic factory context; querying must not read disk or apply config. Export the envelope and module DTOs through the same Rust bindings collector; no module-to-app dependency, Tauri command or hand-written wire strings/TS mirror.
14. Queries only copy published/held data: no native probe/acquire/release, worker start, observer install, filesystem read, config apply/write or window. Runtime fields are coherent with one another. Lifecycle, held diagnostics and runtime are separately sampled during transitions; document that a response is an observation, not globally atomic across those cells. A published `Running`/locked/`inactive` result is normal. Never hide a failed release as inactive, or promote a missing complete lease to active. Lock knowledge may reset to unknown independently of pending cleanup. Active proves owned IOPM prevention, not immunity to lid close, forced sleep or low-battery policy.

## Acceptance criteria

- [x] KA02-01: Generic production registration/control/config recovery works; default-disabled Keep Awake starts no native activity and adds no TCC request, CLI, webview or independent toggle.
- [x] KA02-02: Locked startup runs without acquisition; unlocked startup acquires once; lock releases/unlock restores all-three prevention without Bar.
- [x] KA02-03: Disable/pause/stop cancel and join; release failure surfaces lifecycle cleanup error and retains pending IDs/status until bounded cleanup resolves. Late work cannot resurrect resources or affect a successor; resume resolves pending cleanup and refreshes lock first.
- [x] KA02-04: One worker/subscription/timer per generation, two-second owned reconciliation and notification coalescing survive dropped signals and unchanged reloads without duplication.
- [x] KA02-05: Initial unknown/acquire failure attempts rollback and supports generic Retry; absent-key compatibility is unlocked, not unknown. Live failures report acquiring during outstanding acquisition, releasePending during cleanup or unresolved failure, and inactive only after confirmed cleanup; retain failed cleanup ownership, recover on bounded refresh and avoid log spam. Observer failure uses visible probe-only fallback.
- [x] KA02-06: App-owned typed/read-only status is available in every lifecycle state, including acquiring and in-progress/pending cleanup; assertion/lock/conditions remain truthful, with assertionReleaseFailed only on actual failure. Held file diagnostic overrides registry diagnostic, preserves last-good runtime and clears on identical-good repair. Queries cause no native, filesystem or configuration effects.
- [x] KA02-07: Fake races prove bounded dispatch/cancellation, stale-candidate disposal, prompt published reads during barrier-blocked native creation/release and identity safety without imposing impossible SDK lock rules. Such reads never falsely claim inactive or fully adopted active prevention.
- [x] KA02-08: Generated DTO checks and all validation pass; behavior docs describe limits honestly; proxyAudio behavior stays unchanged and manual cases are explicitly marked unverified if not authorized.

## Tests

- Fake backend transition table: disabled, unlocked start/inactive → acquiring → active once, locked start/no acquire, normal lock-release/active → releasePending → inactive only on confirmation, unlock-restore, repeated lock/unlock, pause/disable then late unlock, resume after lock changes and repeated stop/drop. No assertionReleaseFailed on successful in-flight acquisition/release/rollback; actual failure sets it and leaves releasePending until confirmed cleanup.
- Fake barriers/scheduler: lock/unknown/stop races with acquisition; candidate completion after cancellation; old callback after new generation; old removal/drop cannot release successor; partial subscription/start/spawn failure cleans up; no mutex held during native calls. Query during barrier-blocked native creation/candidate validation returns acquiring promptly, never inactive/active. Query during barrier-blocked normal release or cancelled/stale-candidate rollback returns releasePending promptly, without assertionReleaseFailed unless cleanup actually fails; confirm inactive only after all outstanding work/candidates/IDs resolve. Verify publication precedes the first native creation/release/rollback call.
- Fake time: notification storms/drop/coalescing, always-on two-second reconciliation while active, observer-unavailable fallback, cancellation wakes wait without advancing the full interval; inactive runtime has zero workers/timers/effective subscriptions.
- Failure matrix: initial null/unreadable dictionary/present nonboolean probe and acquire failure, Retry; valid dictionary/key absent starts unlocked, explicit booleans map correctly. Live probe failure suppresses/acquires nothing and attempts release; next success restores only after cleanup. Acquire/partial-rollback failure, lock/unknown reconciliation release failure and stop/pause/disable release failure retain correct IDs, `releasePending` and `assertionReleaseFailed` even when not running. Bounded retry/recovery confirms exactly-once successful release (failed attempts may retry), blocks successor acquisition without duplicate prevention and cannot release a successor's IDs. Verify Drop attempts are not confirmed-release evidence. Simultaneous observer/probe/release conditions, later-start subscription recovery and changed-condition-only logging. No guessed unlocked fallback beyond the approved absent-key mapping.
- Router/serde/bindings: exact four-state assertion enum/app-owned envelope, omitted/null/empty params, invalid params and unknown method; Disabled/Paused/Failed/Running-locked, acquiring and releasePending status; zero backend/filesystem/config-apply query effects; file-first then registry diagnostic precedence; deterministic generated output and exact revision string.
- Host/socket fakes: after a running lease, write malformed JSON, wrong boolean and delete the config file; process normal watcher/reload, then query actual `keepAwake.status` over the existing socket. Each rejected file exposes the held diagnostic and preserves accepted config/revision/runtime/lease; restore identical last-good bytes and verify both held store and snapshot diagnostics clear without lease churn. Also test tray Enable/Disable JSONC edits, session Pause/Resume without disk writes, malformed initial recovery, inert duplicate watcher echo, generic Retry and shutdown cancellation. Assert no new CLI/completion/UI surface and no proxyAudio changes; generic factory-context regression tests preserve existing consumers.
