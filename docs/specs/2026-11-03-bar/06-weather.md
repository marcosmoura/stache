## Requirements

- Keep `auto` (Visual Crossing if nonempty key else Open Meteo), forced `visual_crossing` (unconfigured without key), and `open_meteo` (no key); these are the shipped snake_case `weather.provider` values in `bar.toml` (legacy `visual-crossing`/`open-meteo` are converted only by `stache config migrate`). Preserve actual UI `isProviderAvailable` logic: auto works without an env path/key, despite contradictory legacy Rust `is_enabled` comments. Audit provider normalization/weather-code icons/units/feels-like/default-location resolution and HTTP error behavior from actual provider files, not type comments. Label remains `Math.ceil(feelslike || 0)°C`, `Loading...` when no current data, null when unconfigured, legacy icon fallback.
- Location chain: CoreLocation → `weather.default_location` (legacy `defaultLocation`; city name via Open-Meteo geocoding or coordinates, parsed as legacy). No webview `navigator.geolocation`, no ipapi.co/ipinfo.io, no reverse geocoding. One read per weather refresh (every `weather.refresh_interval` minutes, default 20, and on reconnect), not continuous updates; bounded retries/in-flight requests, cancellation/generation checks on stop/reconfigure; late callbacks after stop or a newer read never republish. Zero location workers/observers/managers when Bar is disabled, paused, failed, gated or in the zero-size no-panel state.
- `precise_location` (bool, `#[serde(default)]` `false`): `false` requests kilometer-level accuracy and accepts the user's macOS approximate-location choice; `true` requests best accuracy and, where macOS requires it, temporary full accuracy only when the user's setting allows. The implementation picks and documents the exact CoreLocation API (for example `kCLLocationAccuracyReduced` versus `kCLLocationAccuracyKilometer`). Migration materializes the default (legacy has no key). Schema/template/doc comments regenerate from `BarConfig`, never hand-edited; the `default_location` doc comment (`config.rs:48`, "when geolocation fails") is updated to the new chain. Reconfigure applies at the next read without restarting Bar.
- Consent: one when-in-use-style prompt is approved. The implementation determines the correct authorization call for the Accessory-policy app on macOS 26 and the required usage-description key(s). Denied, restricted, Location Services off, not determined after a bounded timeout (about 10 s), unavailable, error or timeout → `default_location`, never a bogus coordinate, never a repeated prompt (no re-request after a decided status; `precise_location = true` never re-prompts), typed diagnostic outside Bar visuals. A pending consent decision triggers an immediate weather refresh. Do not promise prompt-free location; no Wi-Fi permission piggyback.
- Delivery: coordinates plus source `coreLocation | defaultLocation` (no address) reach the UI weather fetch as a typed DTO through the Bar bridge. Coordinates never appear in logs, errors, generic host status events, persisted query keys/localStorage/zustand or cross-window sync (same boundary as the key).
- Retain source API shapes: Visual Crossing `https://weather.visualcrossing.com/VisualCrossingWebServices/rest/services/timeline/<encoded-location>/next5days` with metric/icons2/current,hours,days; Open Meteo `https://api.open-meteo.com/v1/forecast` with timezone auto/forecast_days5; city resolution `https://geocoding-api.open-meteo.com/v1/search` with count1/language en. Pin CSP `connect-src` to exactly these three hosts, not wildcard connect/remote script/eval. Preserve audited request fields and normalized current-condition/icon results. Keep API fetches in scoped UI with mocked transports, no general Tauri HTTP permission. Invalid response/status/timeouts enter existing error/data states, never fallback to fake weather or alter provider selection silently.
- Read `VISUAL_CROSSING_API_KEY` from configured env file using injected config directory/home, trim/tilde/absolute/config-relative rules from 01. Actual legacy `config/env.rs` and `platform/path.rs` resolve relative to provided config directory; `weather.rs` falls back to `.` when config path absent. Explicitly document this CWD fallback removal and destination-directory migration ambiguity, not falsely claim all legacy paths were CWD-based. No process environment mutation or secret in logs, errors, query keys, localStorage/zustand, cross-window synchronization or generic host-status events. Narrow generated read contract is Bar-authorized; private query config does not persist or broadcast the key.
- Accepted weather config reload invalidates/refetches only relevant cached data; old location/request/key response cannot replace a newer revision. Env file errors produce absent key plus redacted actionable diagnostics; config/schema listing reads no key. Define env reads on accepted config load/refetch, no undocumented watcher framework. Native I/O off-main and bounded; stale result dropped.
- Weather click opens only Apple Weather through 05's fixed action path: additive `BarAction::Weather` → `BarTarget::Application("com.apple.weather")` in `src/crates/app/src/bar_actions.rs`, never a widget; appearance unchanged. Add generated enum/commands/capability access additively, no arbitrary URL input.

## Decisions (orchestrator, architecture)

- The usage-description `Info.plist` is merged through Tauri's own mechanism. The worker confirms which one applies (`src/crates/app/Info.plist` auto-merge or `bundle.macOS.infoPlist` in `tauri.conf.json`) and whether dev builds embed it, and records the answer in the docs.
- When the running main bundle has no location usage-description string (for example the unbundled dev binary), the adapter does not call CoreLocation; it falls back to `default_location` with a typed diagnostic.
- Refresh interval (user, 2026-11-10): `[weather] refresh_interval` minutes, default 20, range 5–1440, migration writes 20; replaces the fixed 20-minute cadence. It reaches the UI as the non-secret `refreshIntervalMinutes` in the `bar_weather` answer and applies after a config reload without restarting Bar.

- Live run (2026-11-10, macOS 27.0, user-approved, diagnostics since removed): `locationd` and `CoreLocationAgent` logs showed two blockers. The unbundled dev binary has no bundle (`bundleId` null), so `CoreLocationAgent` logs "client bundle is NULL. Skip showing AuthPrompt": **`bun run tauri:dev` never shows the prompt** and falls back to `default_location` after the 10 s wait. The bundled `.app` is signed with the hardened runtime, and without the `com.apple.security.personal-information.location` entitlement `locationd` logs "Client has supported the hardened runtime but doesn't have the entitlement, not sending #AuthPrompt". With `src/crates/app/Entitlements.plist` (only that key, referenced by `bundle.macOS.entitlements`) a debug bundle launched through Launch Services showed the prompt, the user approved, the status became authorized with full accuracy, `requestLocation` delivered a fix and `bar_weather` answered `coreLocation`. A consent left open longer than the 10 s read falls back to `default_location` for that answer and never blocks the UI, but the adapter keeps its single manager and delegate alive only to observe `locationManagerDidChangeAuthorization:` (a consent watcher: no re-request, no `requestLocation`). When the user decides (authorized, denied or restricted) it releases the manager and notifies once; the weather service drops its 60 s cached outcome and bumps `BarView.weatherEpoch` (a decimal-string counter, no coordinate or key), Bar emits a `BarChanged`, and the UI refetches immediately (the epoch is part of the non-secret query key; the previous reading stays shown until the new one arrives). The watcher is cancelled (manager released, nothing notified) when Bar stops, pauses, is disabled or fails, or the runtime generation changes, and a decision arriving after that bumps nothing.
- Live provider traffic (same run): with no API key `auto` used Open-Meteo; `bar_weather` answered `coreLocation` and the Bar showed the temperature, so `api.open-meteo.com` passes the pinned CSP. Unverified live: Visual Crossing (needs a key) and Open-Meteo geocoding (only used for a city-name `default_location`).
