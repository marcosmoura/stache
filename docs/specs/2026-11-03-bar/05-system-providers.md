# 05 — Clock, CPU, battery, Wi-Fi and fixed actions

Read when connecting system data after 04 and separate approval. Visual ownership remains part 04; extend its fixtures, do not change styles.

## Scope

Add `modules/bar/src/providers/{cpu,battery,wifi}.rs`, safe adapters/fakes in `macos/src/`, app bridge/bindings/action projection, UI provider hooks and colocated tests. Clock may stay a local deterministic time-derived React Query value as legacy, not a needless native roundtrip. Reuse the landed `CommandExecutor::run_captured`/`run_captured_prepared` (`sdk/src/commands.rs:847,864`; caller deadline, separate bounded stdout/stderr, cancellation, typed overflow/timeout) for system probes; do not build a Bar-local capture wrapper. Reuse `ApplicationControl` from main, not a Bar shell framework.

## Requirements

- Clock preserves `Intl.DateTimeFormat('en-US')`, 24-hour weekday/month/two-digit day/time with seconds assembled as `Clock.state.ts`, 1s cadence and system timezone. Freeze timezone/time in tests. Timers stop with surface/runtime, not global forever.
- CPU preserves rounded usage/temperature, temperature nullable, valid 0<temp<150°C. Temperature comes from native SMC only (overview Decision 12, revised 2026-11-10): an own `stache-macos` adapter over public IOKit (`AppleSMC` user client, `IOConnectCallStructMethod`), smctemp-style per-chip CPU key lists (legacy TC/Tp/Te/Tf families plus the M1–M5 lists smctemp and Stats use), average of valid CPU keys, invalid-value retry within one bounded sample and a bounded last-valid value before unknown (smctemp's M2 instability handling). No `ismc`/`smctemp` subprocess, no `smc` crate requirement, no private HID API. Unknown temperature remains unknown. Preserve 2s cadence and >=85°C icon/red threshold. Native SMC feasibility on target hardware is gated.
- Battery via `starship-battery` or safe IOKit projection preserves legacy percentage/state/absence and icon map. 30s charging, 120s otherwise; no battery hides component, Full=100%, compact percentage at <=2036px, otherwise legacy state label/color. Read providers off-main and publish complete DTOs; failure never invents charge/temperature/SSID.
- Wi-Fi safe native power/interface/RSSI first where prompt-free; SSID uses the audited `ipconfig getsummary <interface>` compatibility path, enabled by default after the approved feasibility run on macOS 27.0 (2026-11-10; macOS 27 evidence satisfies the macOS 26+ gate by user decision, macOS 26 itself not separately verified). No Location permission request/entitlement workaround or private Apple80211 fallback. Use typed interface identity, bounded runner and legacy summary parsing; sanitize/bound untrusted output. Unavailable/redacted SSID stays null; do not infer disconnected merely from missing SSID. Preserve Unknown/Off/Disconnected/Connected, labels and RSSI thresholds -60/-70/-80, 5s maximum sampling cadence, native change signals/coalescing where feasible. Gate failure is documented degradation, not a new prompt.
- Providers start only for accepted enabled/unpaused Bar; one owned sample schedule, bounded in-flight work/queues, no sample overlapping itself and no storm catchup. Slow/hung read cannot block host/main/other providers; use cancellable bounded adapter/runner and identity checks, retained owner for unresolved native work. Stop cancels, wakes and drains exact-generation workers/children; late completion cannot republish. Stage reconfigure until accepted revision. Error/unavailable projection follows legacy visual fixture branches, with typed diagnostics outside Bar visuals; no new warning UI.
- Fixed typed action enum: CPU→Activity Monitor (`com.apple.ActivityMonitor`), Clock→Calendar (`com.apple.iCal`), Battery→`x-apple.systempreferences:com.apple.Battery-Settings.extension`, Wi-Fi→`x-apple.systempreferences:com.apple.wifi-settings-extension`. Weather/Media enum cases arrive with 06/07. Host determines target, accepts no arbitrary name/path/URL/argv and validates real Bar caller identity. No general `open_app` command or Settings/widget surface. Preserve click/hover styles exactly.
- Reuse main's exact application resolution/open/issuance-permit adapter (`ApplicationControl`, `macos/src/applications.rs:657`). Its `open` (`:1459`) takes `(AcceptedActionToken, &Path, completion)`, a file path only, so the two settings targets extend the landed `stache-macos` `settings` opener (`src/crates/macos/src/settings.rs`, main-thread `NSWorkspace openURL:`; today only `ACCESSIBILITY_SETTINGS_URL` `:20` and `open_accessibility_settings()` `:53`) with two fixed-constant operations, plus a Bar-side opener seam (the app's `SettingsOpener`, `app/src/access.rs:210-215`, has one method); do not add arbitrary URL support. Bound acks and distinguish stale/not issued, issued/completed, refused/not installed, timeout-before-issuance and uncertain-after-issuance; no automatic retry after uncertainty. Return concrete Rust serde/Specta outcomes in generated command result data (`Response::Ok` data if routed through IPC), never JSON-string errors or claims that issued means launched. Cancel stale clicks after runtime shutdown; current action revalidates authorization/generation at native send.
