Test: Tiling and Bar running across hotplug, no attached display left `Absent`; Bar off leaves Tiling at no host topology.

## Requirements

### Native evidence gate

- First compile-prove a public AppKit `NSPanel` nonactivating Tauri webview path on macOS 26. All Cocoa objects, tracking areas and observers remain main-thread-owned; safe Send-facing handles carry only opaque identities. No unchecked `Send`/`Sync`, raw pointer transport or legacy `object_setClass` assumption without proof. Only `stache-macos` contains authored unsafe code. Gate must verify that Tauri can own/close the real panel and embedded webview, not merely apply a style mask to an ordinary window. Before 04, any separately approved live panel probe uses an already implemented test surface, never an unknown Bar route or production Bar factory.
- Target legacy transparent/undecorated/no shadow/no effects/dark/accept-first-mouse/nonactivating behavior, all Spaces + stationary, primary only, no forced `fullScreenAuxiliary`. Clicking controls does not activate Stache, steal keyboard focus or disturb frontmost application except the approved target-launch action. Level is below normal windows (`BelowNormalWindowLevel`, overview Decision 3), legacy's effective level after always-on-bottom overrode the menu-level key; not menu level, not status level. Record layering and fullscreen observations; conflict with the approved legacy evidence blocks acceptance, not silent redesign.
- Public API gate precedes any private SLS proposal. If insufficient, record exact failed cases and ask separate explicit permission for the smallest `stache-macos` private adapter; no fallback is preauthorized. Read-only probes/compile success do not pass native feasibility. Each live gate requires fresh approval and cleanup evidence.

### Native evidence (2026-11-09, user-approved probes on macOS 27.0)

The probes and the live run below ran on macOS 27.0; by user decision (2026-11-10) macOS 27 evidence satisfies the macOS 26+ gates. macOS 26 itself was not separately verified; the app minimum stays macOS 26.0.

| Approach                                                                                                                               | Click activates Stache | Close                                                                                                                                                         |
| -------------------------------------------------------------------------------------------------------------------------------------- | ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Tauri window + `NonactivatingPanel` bit set after creation                                                                             | yes                    | clean                                                                                                                                                         |
| `object_setClass` of Tauri's window to an `NSPanel` subclass (legacy-style)                                                            | yes                    | crashed 3 of 4 runs: KVO `NSRangeException` (`_windowLayerContext`, `opaque`), the window is already `NSKVONotifying_TaoWindow` and the swap splits observers |
| `stache-macos` `NSPanel` created `Borderless \| NonactivatingPanel` at init, Tauri's `WryWebView` moved into it, Tauri's window hidden | **no**                 | clean                                                                                                                                                         |

The third approach is the implemented design: Tauri owns the window and webview; the webview is displayed inside a non-activating `NSPanel` owned on the main thread by `stache-macos`, and is moved back before any Tauri close. No class swap, no private API.

BAR-03-01 live run with the committed host (`377512b`, 2026-11-09, user-observed): clicks with Ghostty/Zed frontmost never activated Stache (logged), hover reacted while another app was active, normal windows covered the panel (below-normal level), close was clean (`teardown: outcome=clean`, no stray process). Native Spaces and fullscreen Spaces also behaved, but they are not a Stache priority (Stache does not build on native Spaces); `canJoinAllSpaces | stationary` is kept for legacy parity (user decision 2026-11-09).

### Owned lifecycle

- Implement `WindowKind::NonActivatingPanel` semantics additively; `Standard`/test window and unsupported `Launcher` unchanged. Factory construction/configure are inert. SDK session gate currently spans backend calls: backend open/close/release remains enqueue-only, cannot synchronously wait/reenter while holding it. Stage logical identity/reservation then receive async native/page-loaded acknowledgement outside that gate. Distinguish requested, native-created, loaded, failed and cleanup-pending; do not report panel ready/loaded on queue acceptance. Bound acknowledgment waits off-main; page-load failures/timeout clear reservation and expose typed failure.
- Use exact owner/runtime generation/window identity for queued creates, focus, reposition and close. Every native commit rechecks cancellation/topology/config identity; late creation/load callback or old close cannot resurrect or close successor. Nonactivation means Bar reuse must not inherit Standard's `set_focus` path.
- Primary display is `NSScreen.screens[0]` (menu-bar display, origin 0,0), never `mainScreen` (overview Decision 3). Reuse the landed `macos/src/displays.rs` (`DisplayInfo` `frame` with origin, `visible_frame`, `is_primary` = index 0, `is_main`; `DisplayLayout::primary()`/`primary_height()`; `DisplayControl::query()`/`observe_topology()`, as Tiling wires it at `app/src/host.rs:748`); do not extend `desktop::DisplayFrame` or `ScreenRecord`, and do not duplicate. Project display IDs with `app/src/display.rs` `sdk_display_id`. Primary frame uses logical primary bounds/origin and `(padding, padding, width - 2*padding, height)` relative to that display; account for scale and negative origins, no double scaling. Hotplug/primary/scale change coalesces signals, recomputes one panel and atomically moves reservation. No-primary state is explicitly unavailable with no guessed screen or stale reservation; recover on topology change. Zero size (overview Decision 16): explicit `height = 0` or computed width `width - 2*padding <= 0` is valid; Bar runs with typed status "no panel: zero size", creates no window and publishes no reservation, and reconfigure moves between no-panel and panel states in place. Shared window validation stays unchanged; no wrap/clamp or new schema restriction. Every Bar owner with a panel reserves the approved constant sum, including explicit values.
- Reconfigure preflights outside short published locks; use the accepted-config watch for actual committed config/revision, not disk or guessed future revision. Reject keeps old frame/providers. Unchanged reload/tray echo does not duplicate resources. Disabled/paused start no Bar workers/webviews/timers/subprocesses; pause/disable/failure clears reservation immediately. Constant top `height + padding` while menu slides away, never follow the animation with inset updates.
- Stop first invalidates generation and wakes waits, then removes callbacks/closes exact panel and joins owned workers off-main. Bounded native removal acknowledgment returns success only on confirmation; timeout/failure retains inert main-thread owner with exact-ID cleanup retries and truthful cleanup-pending. Never drop Cocoa guards on a worker or forget ownership because a deadline passed. New generation cannot be harmed by retained cleanup. Partial start/install/page-load/spawn failure uses the same rollback. No locks held across native calls, waits or joins.
- Reuse the landed `ModuleFactory::begin_shutdown`/`finish_shutdown` stage runner and `NativeOwner`: invalidate/wake factory/native/data waits before IPC/worker joins, registry reverse stop before factory finish/drain/drop. A hung background provider must not block main, host commands, bridge reads or shutdown ingress cancellation; native synchronous APIs cannot be promised forcibly interruptible, so quarantine bounded outstanding work with retained ownership and report uncertainty rather than waiting forever. Known Cmd-Q/logout host routing gap remains out of scope.

### Menu bar and data bridge

- Audit legacy `menubar.rs`/`watcher.rs` and `Bar.state.ts`: `menuHidden` means menu visible, causing Bar translateY(100%)/opacity 0. Seed initial state and subscribe before refresh, reconcile dropped/coalesced signals. Event-driven display/menu/activation observations where feasible, smallest bounded poll only while needed; document macOS heuristic limits, unknown/error behavior and deduplicated diagnostics. Preserve actual reveal/hide timing and animation in 04, no polling-derived visual redesign.
- SDK EventBus is pull-only/lossy. Host owns bounded pull workers/state subscriptions, recovery snapshots and concrete tauri-specta `collect_commands!`/`collect_events!` entries in `bindings::builder`. App `BarView` reads published cells only, not native/module locks; exact provider revision/generation/sequence and held file-first diagnostics survive projection. Commands/events have concrete generated DTOs; no handwritten TS names or generic JSON facade. Future providers fill typed optional fields, not forward-invoked functions.
- Least-privilege route-bound authorization validates actual window label/owner/surface, not a caller-supplied surface argument. Expose only current read feeds; no filesystem/shell/plugin HTTP/general launch/config writes. Part 04 adds the capability when the route exists; part 08 adds only authorized generic session actions.
- While Bar is not running (disabled, paused, failed, stopped or held by the Accessibility gate), bridge commands return a typed unavailable result, never stale data or a hang.

### Accessibility gate interaction

Bar needs no Accessibility permission; the shipped [gate](../2026-11-07-accessibility-gate/00-overview.md) applies its baseline requirement to Bar automatically. Extend the landed per-surface `WindowChrome`/`chrome_for` (`src/crates/app/src/windows.rs:40,56`) for the `bar` surface instead of a parallel chrome path. Bar's stop path is the ordinary registry stop, so revocation through `on_permission_change` tears down its panel and clears its reservation with no Bar-specific hook; while gated Bar never starts and owns zero windows/webviews.
