## Requirements

- **Published state.** Reuse the landed SDK machinery (`StateSchemas::with`, `ModuleContext::state_publisher`, `StatePublisher::publish`, `observe_state` in `src/crates/sdk/src/{published_state,context}.rs`). Register schema `tilingState` v1 (provider ID = Tiling's module ID) next to `keepAwakeStatus` v1. Tiling's generation-scoped publisher in `published.rs` owns a minimal DTO: workspaces (name, screen, visible, focused, order), windows (opaque per-generation key as decimal string, app name, title, workspace, minimized/hidden) and focus (workspace, window). Envelope carries exact runtime owner/generation, accepted config revision, state sequence, schema identity; all u64 crossing JS are opaque decimal strings. Atomic payload/revision, publish cell before bounded notification, subscription-before-fetch/race-free resnapshot, stop tombstone rejects late writers. No native token or pointer crosses to JS. Never use lossy EventBus alone as state.
- **Projection.** The app projects the DTO into typed `BarView.tiling` (`null` until resolved) through a no-timeout watcher, like Keep Awake. The projection owns a never-resetting change counter, because the SDK sequence restarts per generation (`bar_bridge` sums sequences). Bar declares optional `observes` Tiling, never `requires`. SDK/Bar never imports Tiling types/crate/config; the host passes controlled display data to the UI, not arbitrary JSON pretending to be another provider.
- **Strip data (legacy semantics).** All workspaces, sorted in the UI by legacy order terminal/coding/browser/music/design/communication/guitar/misc/files/tasks then unknown alphabetical; the windows of the globally focused workspace, excluding minimized and hidden ones (`!is_minimized && !is_hidden`); a native tab group shows only its active tab; the focused window.
- **Click actions.** Clicking a workspace focuses it; clicking an app focuses that window. `bar_tiling_action` takes a closed enum `focusWorkspace{name}` | `focusWindow{window}` plus the rendered Tiling generation/sequence and checks the live Bar label. The host resolves the opaque window key to the exact current token; Tiling revalidates at issuance through `Intent::FocusWorkspace` / `Intent::FocusWindow(FocusTarget::Window)`. Typed outcomes (applied/stale/unavailable/busy/unauthorized/…, enumerated concretely). An outcome produces no UI (`console.debug` only); the strip changes only through the next `BarChanged`. UI cannot inject raw native tokens/pointers or bypass module enable/quarantine. No generic dispatcher.
- **Independence and empty/loading.** Bar absent/disabled/stopped/failed and Tiling absent/disabled/paused/failed work independently: no circular lifecycle requirement; other status components keep running. Tiling still manages windows without Bar; Bar still shows status without Tiling. `SpacesFallback` "Loading..." shows only while Tiling is Running and its first state is unpublished. The empty `<div />` shows for absent/disabled/paused/stopping/failed/tombstoned/schema mismatch/zero workspaces. Reconciling/incomplete phases render whatever is published. A snapshot error stays an explicit query state, never a fabricated stale active provider, and renders `<div />`.
- **Reservation lifecycle.** With landed 05 normalization, verify from the real host bridge that an active Bar's constant top inset applies while slid hidden, the inset staged at panel open is held while the page loads and a failed panel clears it, an exact-generation tombstone clears on stop/pause/disable/failure, and a stale release cannot clear a successor. Reuse 05's per-edge max mathematics; do not re-implement or re-own it, and keep no `bar.height`/config reads.
- **Visuals identical:** port actual legacy `Spaces/**`, AppList, icon maps and transitive primitives/hooks/styles; no redesign/extra badge/tooltip/loading treatment. Exact workspace icons; app map keeps every legacy entry (U+200E hidden-mark WhatsApp, Microsoft Edge Dev, `DashboardCircleIcon` fallback) plus the approved additions keyed by exact `CFBundleName`: `Zed` → `CodeSquareIcon`, `Aside` → `AiBrowserIcon`, `Herdr` → `CommandLineIcon`, `DeviceHub` → `SmartPhone01Icon`, `AIOStreams` → `PlayListIcon`, `Nuvio` → `Tv01Icon`, `FigCraft` → `PaintBoardIcon`. Unknown workspace renders without an icon (legacy's undefined icon crashed the whole Bar); no new fallback. Preserve app order per focused workspace, duplicate-name title selection/truncation (40 characters + `...`, laptop25), focused-label-only appearance and laptop focused-app reduction at viewport width<=2036.
- Preserve grid-auto-flow/6px gap/0 10px padding, opacity0.68→1/crust focus, workspace surface1 indicator radius12 and motion spring bounce0/durationSlower, app width0↔auto/opacity0↔1 and length-scaled motion duration, loading fallback, reveal/exit/intermediate animation behavior. Reuse approved Bar fonts/colors/spacing/Surface/Button/Icon computed values.
- **Icons.** `@hugeicons/core-free-icons` stays 4.4.0 and `@hugeicons/react` 1.1.10. The parity reference takes icon SVGs from the 4.4.0 package, independent of the new components; all other markup/CSS/layout comes from the pinned legacy reference. List every strip icon whose 4.2.3 and 4.4.0 glyphs differ.
- Extend the **independent** Bar reference manifest (`src/ui/tests/bar-reference/manifest.json`, extracted by `scripts/bar-reference/extract.ts` from `_legacy/app/ui/renderer/bar/Spaces/`; today it lists only Spaces index/styles/`Spaces.tsx` with stubs for `Spaces.state`/AppList/WorkspaceList) and the parity gate `src/ui/tests/bar-parity/` (`bun run test:parity`) with pinned legacy Spaces/AppList/maps/transitive source object/hash/provenance, font/browser/OS/scale/profile/data/animation timeline. The seven new app-map entries record the 2026-11-10 user decision as provenance instead of a legacy source. Reference is extracted read-only markup/CSS/SVG reviewed against originals or user-approved screenshots with measurements; never derived from new components/helpers or baseline auto-updates. No legacy runtime/build/automation. Missing font/baseline is blocked/unverified, not similarity pass. Exact screenshots, computed geometry/styles/SVG and animation samples; narrowly justified raster tolerance requires explicit approval.
- UI reads state from `BarData` (`BarView.tiling`) with generation/change-counter ordering, subscribe-before-fetch and stale-response rejection. zustand only if a slice needs UI-local state. StrictMode/late unlisten disposal, provider disappearance and schema mismatch remain bounded/inert. Keep existing generated surface/capability least privilege and earlier UI unchanged.
- **Performance.** No idle timers or polling. After the part, run `bun run measure:bar` on a release `.app` and compare with the [2026-11-10 baseline](../2026-11-03-bar/measurements/2026-11-10T19-33-59-056Z/report.md) (+0.59 % of one core, +0.39 wakeups/s).
- Final integration exercises **landed** accepted-watch, host shutdown ordering, input HQ>MA>KB with passive Tiling, Bar reservations/optional state, noTunes applications identity and sibling disabled/failure recovery. Publish actual native limitations/capabilities and performance evidence from [validation](../2026-11-03-tiling/validation.md), not an unsupported universal-window claim.
