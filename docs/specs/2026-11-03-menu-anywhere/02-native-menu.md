# 02 — Native menu adapters

Read when implementing AX ownership and native rendering. Approval is required before this part and separately for each real native run.

## Scope and files

Adapter code only; no module runtime, event tap, production factory or enabled behavior. Depends on Part 01 for crate layout, not config policy. New planned files under `src/crates/macos/src/menu/`: `mod.rs`, `snapshot.rs`, `reader.rs`, `presenter.rs`, `invocation.rs`, `testing.rs` and adjacent `tests.rs`. Export narrowly from `src/crates/macos/src/lib.rs`; update that crate's `Cargo.toml` only for required framework features. Update adapter inventory in `docs/architecture/overview.md` on acceptance. Add an opt-in `menu-native-check` dev-tools binary under `src/crates/app/src/bin/` with explicit Cargo target wiring only for the approved manual gates; default tests cannot invoke it.

Extend existing `src/crates/macos/src/applications.rs` (`ApplicationControl`, `ApplicationId`, `ApplicationObservation`, `IssuancePermit`) and its `applications/testing.rs`, `applications/tests.rs` with a minimal additive exact retained-instance activation operation and fake/barrier tests. Rebase and require the landed [Hold-to-Quit frontmost observation/identity extension](../2026-11-03-hold-to-quit/03-applications-frontmost.md). That part adds graceful termination, not activation; this part owns activation. Current main's resolve/open operations are not exact activation. Keep all retained application instances in its existing main-owner maps; preserve noTunes force termination, open and Hold-to-Quit graceful operations. The Menu adapter's reader/presenter can be committed independently, but this part cannot be marked done without the real frontmost/activation integration compiling.

Planned public concepts: `MenuSnapshot`/`MenuItemSnapshot` (pure `Send` data), opaque `PresentationId`/`ActionToken`, `MenuReadOutcome`, `MenuPresentationOutcome`, `MenuInvocationOutcome`, and a `MenuControl` handle with acknowledged cancellation/cleanup. Names may adapt to landed conventions; capabilities and outcomes may not be dropped. These are not shipped APIs.

## Ownership and compile gates

Use one dedicated AX owner thread: it creates, queries, retains, presses and releases AX elements. It owns a map keyed by unique presentation ID and action token. Root/menu/children/attribute copy results obey CF create/copy ownership and type checks on every path. Elements needed by actionable leaves remain retained until presentation cleanup, and a selected action owns a lease until `AXPress` returns even if tracking has closed. No `NSValue` raw-pointer association, leak-dependent lifetime or blanket unsafe `Send`/`Sync`.

The presenter and all `NSMenu`/`NSMenuItem`/target/delegate objects remain main-thread-owned in an exact-presentation map. Cross-thread messages contain only pure snapshots, IDs, geometry and typed results. Menu actions only select/enqueue a token with panic containment; no synchronous AX work or worker wait in Cocoa callbacks. Main dispatch closures look up native state on main rather than capture non-`Send` native objects. No 1.5 s menu-tree traversal on the app main thread.

Before implementation acceptance, compile the real ownership types and FFI/binding features on the retained toolchain, prove `Send` bounds for channel messages and that native types stay owner-local, and build the opt-in harness. If dedicated AX ownership cannot safely support the required APIs, stop for an architecture decision; moving the whole traversal to main is not an approved fallback. Include source comments documenting the SDK/header evidence and any narrow unsafe FFI preconditions.

## Reader and rendering

Capture authoritative frontmost `ApplicationId` through the shared applications owner at the first processing opportunity, not inline in a tap callback. Also record trigger timestamp and identity-capture timestamp. This observes frontmost at processing time, not a proven event-time snapshot; reject requests whose capture queue hop exceeds the 2 s native acknowledgement window. Validate the exact instance before creating its PID-based AX root and again after reading/before showing; PID alone is never identity. If the frontmost changed during capture/read, return `StaleTarget`, not a menu for the newly frontmost app. `SelfTarget`, no-frontmost, no-menu, permission denial, unsupported/malformed AX, cancellation, dispatch failure and budget exhaustion are distinct typed outcomes. No retry/cache or stale fallback.

Set `AXUIElementSetMessagingTimeout` to 0.5 s **on each actual element before messaging it**, including root, menu bar, menu items and submenu nodes. It does not propagate to other or equal elements (`AXUIElement.h:387–396`). Timeout-setting failures abort. Start one 1.5 s cumulative read deadline before the first AX read; check it and cancellation before and after every call and each traversal step. Count every visited element against 4096 nodes and depth 16 (root depth 0); detect cycles/repeated ancestry and abort rather than recurse forever. Cap child-array allocation/traversal before accepting an oversized tree. Any structural error, timeout or cap breach discards the entire snapshot and releases all retained state, never a partial popup. Unsupported optional attributes retain the legacy defaults below; transport/time-budget failure is not an optional missing value.

An AX call in flight cannot be interrupted by cancellation or deadline. Worst-case read latency includes the 1.5 s deadline plus one in-flight 0.5 s messaging timeout and scheduling/cleanup overhead. This is an engineering bound to measure, not a hard real-time guarantee; no second read is issued after expiry. Do not change the process-global AX timeout. Cancellation invalidates logical authority immediately while the thread finishes its current call.

Match `_legacy/app/native/src/modules/menu_anywhere/menu_builder.rs:266–405`:

- Skip the first root child (Apple menu), not the first child of every submenu. Empty title or `AXSeparator` is a separator. First nonseparator root item is bold; submenu titles inherit the parent title. `autoenablesItems` is false.
- Missing enabled attribute defaults true; ✓ is on, • is mixed, other/absent mark is off. Only enabled leaves receive actions. Disabled items, separators and submenu parents cannot press.
- Lowercase nonempty AX command characters for native key equivalents so AppKit renders shortcut glyphs; retain Unicode. First `AXMenu` child is the submenu. Do not add an unrelated shortcut-search or glyph-inference feature.
- Correct modifier display per `HIServices/AXAttributeConstants.h:995–999`: Shift/Option/Control bits 0/1/2; Command iff bit 3 (`NoCommand`) is absent. Missing attribute defaults Command; value 0 means Command; 8 means none; combinations preserve the other bits without reintroducing Command.

## Coordinates and tracking

Treat Quartz event points and AppKit screen frames as distinct global coordinate spaces. Pair displays by public display identity and snapshot current geometry on main. Convert against the **primary display's origin reference**, not `NSScreen.mainScreen` or each destination screen's height. For an unscaled shared global-point desktop, `xA = primaryA.minX + (xQ - primaryQ.minX)` and `yA = primaryA.maxY - (yQ - primaryQ.minY)`; locate/validate the containing display with its matched geometry. Explicitly reconcile any public API units with the per-display point/backing-scale geometry; do not multiply all coordinates by a Retina scale. Reject missing/changed/ambiguous geometry or a point outside the display union rather than use a 1080 fallback. AppKit may clamp the menu near edges; request the converted click anchor, not a key-window anchor.

Present only on main after checking live presentation, target identity, runtime generation, captured revision authority and request deadline. Tracking cancellation must execute `cancelTracking` for that exact menu on main. **Mandatory gate:** establish whether current `main_thread::run_on_main` (`dispatch_async_f` to main) actually drains while `NSMenu` is tracking. If not, implement and document a tracking-mode-compatible public run-loop dispatch in this adapter, compile it and verify cancellation during nested tracking. Merely queueing a job that runs after tracking exits is not cancellation success. No synchronous wait on main for the AX owner, lifecycle thread or main queue.

## Invocation and cleanup

Add a separately named exact-instance activation operation to the shared applications adapter, not resolve/open-by-path or activation of whatever is frontmost. Resolve the retained `ApplicationId` and validate liveness/owner generation on main, then issue the public activation send only through the current `IssuancePermit::issue` boundary with presentation authority and cancellation/deadline checks. Reuse current 2 s per-hop acknowledgement, 10 ms cancellation-observation quantum (subject to scheduling), immediate logical invalidation and acknowledged cleanup; no new application store or arbitrary callback/work under the permit. Compile-gate the actual activation binding/features and main-owner types. `Requested` means native acceptance, not proven focus; `Refused` means confirmed false return, not proof of no side effects; `Stale` means no send for this operation; `Uncertain` covers an issued send with lost/late acknowledgement. Pre-send expiry/dispatch rejection remains distinguishable from issued uncertainty. Never automatically retry activation or use a fallback target.

The selected token binds one presentation, captured app instance, runtime generation and presentation revision. Before activation and again immediately before AXPress, recheck validity, permission, exact-instance liveness, deadline and token membership. Activation targets that retained instance using the shared applications adapter, never whatever happens to be frontmost when an action is selected. A changed frontmost before showing is stale; once the menu is shown, action activation may return to its captured target. Termination/relaunch or foreign tokens are stale even with the same PID/bundle.

Use a fresh 2 s acknowledgement/deadline window for each queued native hop; use the shared permit model for exact activation, and an equivalent presentation-specific issuance gate for press. The captured presentation revision remains authorized across enabled reconfigure (Part 03); do not use a global newest-config token that silently revokes the accepted popup. A queued send checks exact app, generation, presentation revision, deadline and abandonment at the immediate send boundary, not just before enqueue. Each send is at-most-once. Activation/press already issued cannot be undone; cancellation between activation and press suppresses the latter but does not claim to undo activation.

Set the selected AX element's timeout to 1 s before `AXPress`. Typed invocation results distinguish `Pressed` (AX returned success, not proof of visible effect), `Stale`/`Cancelled`/`ExpiredBeforeSend` (no press issued), `Unsupported`/invalid element, activation refused, dispatch failure, and `Uncertain` (issued call with lost/late acknowledgement or `kAXErrorCannotComplete`). The header explicitly permits `CannotComplete` after an action ran (`AXUIElement.h:315–320`): never retry automatically or report proven failure. Preserve whether activation already issued when reporting a later press failure.

Stop first atomically invalidates without waiting for a stalled issuance gate. Then request exact tracking cancellation and AX cleanup, using a fresh bounded 2 s cleanup acknowledgement independent of the cancelled lifecycle token. Do not free owner-thread resources still used by native sends. Retain inert cleanup ownership until the AX call resolves and main confirms tracking ended; removal failure/timeout is `cleanupPending` plus a typed error, not successful stopped cleanup. Retry cleanup safely; Drop is best effort, never the proof of success. Late completion/cleanup names only its presentation ID/generation and cannot erase a successor. Keep selected-action resources until press resolves, including uncertain/late outcomes; eventual cleanup releases them exactly once. Do not claim a global shutdown SLA from per-hop budgets.

- [ ] **MA-02-02** Reader enforces explicit per-element timeout, cumulative deadline, depth/node/cycle limits and all-or-nothing output; cancellation cannot queue another AX read after expiry and never claims in-flight interruption.

- [ ] **MA-02-04** Pure geometry tests cover above/below, left/negative coordinates, displaced primary origins, display gaps, Retina/non-Retina mixtures, borders and geometry replacement; native multi-display placement passes its manual gate.

- [ ] **MA-02-06** Compile and approved modal-tracking checks prove exact-menu cancellation, acknowledged cleanup and main responsiveness; failed cleanup remains inert/pending and late cleanup cannot remove a successor.

## Tests and validation

Inject fake AX, clock, dispatcher, geometry, applications and menu backend. Use deterministic barriers before capture, after root creation, between attributes, before show, before activation, before press, inside a stalled send and before cleanup acknowledgement. Race cancellation/termination/reconfigure/successor presentation at each boundary. Cover timeout-setting failure, wrong CF type, missing optional values versus transport failure, no menu, self target, oversize/cycles, dispatch rejection, synchronous callback/panic containment, double selection, abandoned queued jobs, and late uncertain completion after close. Default tests must never construct the system backend in an effectful path.

In existing `applications/testing.rs` and `applications/tests.rs`, record exact activation independently of open/force/graceful termination. Barrier-test before native preflight, immediately before permit commit and after issued activation: cancellation winning prevents send; issuance winning records one activation even if cancellation prevents the later AXPress. Cover Requested/Refused/Stale/Uncertain, same-PID/same-bundle replacement, dispatch rejection, pre-send abandonment, acknowledgement timeout then late return, and successor generation isolation. This fake/real-binding compile gate belongs to MA-02-08; Part 03 only consumes the accepted adapter.

## Per-run approved manual gates

Request approval naming the exact native operation and target PID for **each** run. Use an isolated Next config with all unrelated modules disabled and a disposable test app launched by the tester; never launch legacy or use shared process-name termination. Record timestamps, target identity, display layout, timeout/error and eventual resource counts.

1. Read/show that test app's menu: inspect Apple exclusion, separators, checks, shortcuts, submenus and first-root bold. Test above/below/negative-origin and mixed-scale display arrangements with a click on each screen; record actual anchor/clamping.
2. Hold tracking open, then independently request cancellation from the worker; verify main-dispatched cancellation runs **during** tracking, no action fires and cleanup acknowledges. Also close/select normally and check exact owner counts return to baseline.
3. With separate approval to suspend/resume only the launched test PID, stall a read and then an action; measure read deadline plus in-flight timeout and 1 s press behavior. Resume in guaranteed cleanup. Observe `Uncertain` without retry; do not perform destructive menu actions.
4. With approval for the harmless selected test action/activation, select its instrumented no-op item, terminate/relaunch that test target at barriers, and verify stale drops, exact activation and one press maximum. Quit only the test processes owned by this run. Record pending versus acknowledged cleanup honestly.

No manual gate is run during spec writing. Failure blocks acceptance; build success alone cannot establish modal dispatch, thread feasibility or native timing.
