# 06 — Virtual workspaces and owned application visibility

Read when implementing after 05 and separate approval. This part enables the production factory only once workspace safety is complete.

## Scope

Tiling `src/{workspaces.rs,visibility.rs,actor/handlers/}` and app factory registration/registry tests. Part 03 owns the safe hide/unhide operations in the applications adapter; this part adds only ledger/restore policy and consumes them. No macOS Space switching or per-window offscreen hiding.

## Requirements

- Empty config creates one default workspace per display; configured assignments match main/primary/secondary/name, missing display falls back to main and returns when configured display returns. Preserve per-display visibility (one workspace per present display) and one global focused workspace, focus history and stable ordered window membership. No displays means no frame/hide effects and explicit incomplete topology, not a guessed display.
- New window assignment: first matching configured workspace rule → focused/visible workspace on its owning display → display default. Native title changes update metadata; rules are creation/adoption assignment, not permission to repeatedly move user-managed windows. Send/focus/swap/resize/balance commands retain intended behavior and exact tokens; unhide owned destination app before focus. External hidden/minimized/fullscreen state is respected, not automatically cleared by refresh.
- Preserve non-Grid insert-after-focused-window in the assigned workspace (else append), `_legacy/app/native/src/modules/tiling/actor/handlers/window.rs:147–164`; Grid append is the explicit stable-ten exception from 02. `--preset` applies only in a Floating workspace, not to an individually floating window in tiled workspace (`_legacy/app/native/src/modules/tiling/actor/handlers/preset.rs:21–49`). Preserve silent exit0 actor admission for that no-op; retain internal NoOp reason without inventing an Applied frame/default stdout. Eligible explicit preset outranks newly floating defaultPosition. Config `preset-on-open` has no legacy runtime reads; retain inert, with no automatic preset policy or Grid overflow preset/center.
- Application visibility is global: aggregate requirements across **all visible workspaces/displays**. If any needs an app, do not hide it for another workspace. Leave same-app windows from inactive workspaces visible, keep logical assignments, and publish a conflict/partial-isolation diagnostic. No hide/unhide oscillation, process splitting or isolation promise. This limitation applies also to window-send and app windows on multiple displays.
- Actor ledger records only confirmed runtime-caused visible→hidden transition for an exact application instance; never take ownership of prehidden/already hidden apps. Public hide first; AXHidden fallback only through gated safe adapter with typed confirmation. Unknown issued hide remains pending possible ownership until reconciled; stop conservatively revalidates that exact target and reports ambiguity, never clears it silently. User external show relinquishes confirmed ownership; external hide with no runtime issuance never becomes owned.
- Ordinary workspace hide/unhide effects and callbacks feed ledger through actor, not inline under registry/module lock. Stop uses sealed ledger + separately authorized restoration-only capabilities after normal effects drain. Restore only still-alive exact owned/potentially-issued instances, never replacement PID/app, and only where restoration authority is supported by recorded evidence. Terminal gone/already shown entries clear; failed/uncertain unhide remains pending with IDs/reasons for retry. **Never seal-and-drain then forget failures.** No new normal hide after seal, late old hide cannot issue after completed restore drain.
- Accepted structural reload policy: workspace name is configuration continuity key; retain matching workspace identity, user layout/ratios/floating/order/focus when compatible. Added workspaces use configured layout/default. Removed workspace windows move in stable order to visible/default workspace on same display (main fallback); apply app visibility conflict policy. Changed configured layout intentionally replaces that workspace layout and clears incompatible ratios; unchanged layout retains user override. Default-layout edits affect new/default-following workspaces, not explicit user overrides. Screen-assignment edits move matching workspace after acceptance; rules/ignore changes apply eligibility immediately, preserve existing compatible assignments, newly ignored windows release tiling/owned visibility needs. No rule edit silently reassigns all windows. Prepare complete mapping before acceptance; rejected mapping leaves old state/publication.
- Disabling/pausing/permission loss restores only runtime-owned hides after issuance drain, preserves cleanup quarantine and leaves other modules running. Session state is not persisted across a fully stopped/new runtime; do not advertise cross-restart workspace recovery. A successful config acceptance is separate from partial physical restore/placement. macOS provides no atomic hide-owner attribution against simultaneous external hiding: if issued-hide evidence plus observations cannot distinguish runtime ownership, retain an ambiguous pending record and diagnostic rather than unhide a possibly user-hidden app or claim recovery complete; explicit recovery approval is required for that ambiguous case.
- Factory registration is now complete for core/workspace behavior, default disabled, consuming 05's already-tested host reservation subscription/normalization from first active write. Until 08/09 land, requested animation/drag/borders capability is explicitly unsupported/degraded with diagnostics; no placeholder success or silent config feature erasure.
