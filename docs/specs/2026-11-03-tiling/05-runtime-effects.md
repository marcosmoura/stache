# 05 — Frame effects and core runtime lifecycle

Read when implementing after 04 and separate approval. Bar foundation landed on main as `221b005` and `feat/tiling` was rebased onto it, so its accepted-watch and host reservation contracts are available. Factory is compiled/inert but not production-registered until 06; no incomplete public command success.

## Scope

Tiling: new `src/module.rs` (the `Module` impl of `sdk/src/module.rs` `configure`/`start`/`reconfigure`/`stop`), new `src/outcome.rs` and `src/reservations.rs`; frame-effect code extends the existing `actor/` (`Engine`, `EffectRunner`, `ThreadRunner`, `spawn_actor`), `state::Effect` (`state/mod.rs`), `tracking.rs` (`TrackingRuntime`) and `backend.rs`, with no parallel runtime. App: a factory struct in `app/src/host.rs` following `KeybindingsFactory` (`register`, `ipc_handlers`, `project_status`, `begin_shutdown`/`finish_shutdown`) and fake composition tests. Production composition is the `ModuleFactories::production` base list plus the factories appended in `app/src/lib.rs` (Wallpapers/Keybindings/HoldToQuit); this part does not add Tiling there, 06 does. Reuse landed accepted-watch/factory begin-shutdown/finish and host reservation observation hooks; no parallel lifecycle. Map legacy init/subscriber/executor/cache/window_ops in inventory. Reservations are consumed before the first frame effect, not deferred to 10 or production registration in 06.

## Requirements

- `configure` validates/prepares pure plans, construction is inert. `start` stages observers/actor/effect resources with exact rollback, queues initial enumeration before Running and returns without waiting for all window moves. Missing AX → `ModuleStatus::WaitingForPermission` (`sdk/src/status.rs`); core infrastructure failure → appropriate Unavailable/Failed. Declare only `Permission::Accessibility` with `PromptPolicy::UserOnly` (`sdk/src/permissions.rs`), as landed input modules do: status checks never prompt and only explicit host tray requests may prompt; no Tiling-specific prompt or automatic permission changes. Individual resize refusal is operation degradation, not asynchronous registry Failed. Optional feature capability absence is explicit; no false healthy claim. Status projection adds a Tiling `ModuleStatusView` field following Keybindings' `project_status`. Parts 05/06 register no state schema and publish no `PublishedState`; `Effect::Publish` updates only the internal `SnapshotCell`, and part 10 ([Tiling–Bar](../2026-11-08-tiling-bar/00-overview.md)) owns the schema. Failed-stage rollback is new work: `TrackingRuntime::start_with_clock` installs the backend and spawns the runner with `?` and has no explicit unwind of earlier stages.
- Pure deltas track desired versus **confirmed actual** frames and monotonically changing layout plan sequence (A→B→A distinct). Frame executor sends only changed eligible frames through new frame-write `Effect` variant(s) routed via the existing `WindowBackend::submit_action`/`act` (`backend.rs`); the runtime publishes the action `GenerationCell` issuance authority only while Running (today `TrackingRuntime` leaves it unpublished and nothing outside tests calls the action methods) and seals it at stop; outcomes return to actor tagged by exact window/generation/revision/plan. Acknowledging an old plan cannot clean a new plan. Readback mismatch/refusal/partial size-position records actual frame and unresolved components; never mark desired frame applied on enqueue or a partial setter.
- Consume `ScreenReservationObserver`/`ScreenReservationSnapshot` via `ModuleContext::observe_screen_reservations` or `FactoryContext::observe_screen_reservations`. Tiling never declares `reserves_screen` and never calls `Registry::apply_screen_topology`; host topology application belongs to Bar 03, sequenced after Tiling 01–09, so until then the snapshot lists no displays and every display has zero host inset ([SDK: screen reservations and display identity](../../architecture/sdk.md#screen-reservations-and-display-identity)). Tiling's own native topology (`stache_macos` `DisplayLayout`/`DisplayControl`) still gates writes; once host topology is present, a display absent from it or with a stale generation contributes zero host inset but cannot authorize a write to a reused native display. Display ID projection is `stache_app::display::sdk_display_id` (`app/src/display.rs`); the tiling crate cannot depend on the app crate, so the app factory injects it and Tiling never reimplements it. SDK `EdgeInsets` → `geometry::Insets` conversion lives in tiling `reservations.rs`; `geometry::usable_area` already applies max(native, host) + own gap once. Do not use `ModuleContext::windows()` (the UI-window `sdk::windows::WindowBackend`); AX control stays in `stache_tiling::backend::WindowBackend`. Subscribe-before-fetch to these host reservation snapshots using native typed DisplayId, topology generation, exact reservation owner/generation and monotonic sequence. Normalize reservations measured inward from full display logical bounds: derive native insets from visibleFrame, take per-edge max(native inset, host aggregated reservation), then add own tiling outer gap exactly once. Upstream same-edge max is not a sum; full top0/native24/reservation40/own6 gives top46, not70. Use one logical coordinate space at scales1/2 and negative origins; invalid/nonfinite/infeasible geometry yields explicit no-frame diagnostic, never fabricated safe space. No Bar config reads. Missing active reservations means zero host inset, not loss of native exclusion; incomplete/stale topology cannot authorize a write to a reused display. Snapshot/tombstone changes invalidate plans atomically before deferred recompute; actual send still checks accepted revision, runtime/token/topology/plan authority. Stale fetch/releases cannot overwrite successors. Stop cancels/wakes/unsubscribes with existing lifecycle ownership; failed cleanup stays retained. Part 10 adds final cross-module tests, not this first safety seam.
- Per window/plan, issue each required position/size component at most once, with one bounded readback; retain unsupported/refused capability diagnostics. Only an explicit new user command or meaningful external/config/topology change may create a new attempt, not repeated own AX echoes/periodic refresh. No immediate retry loop or fighting unresizable apps. Minimum-size inference is bounded and reset by balance/new evidence, not infinite enlargement.
- Reconfigure stages fallible pure/resource changes then consumes the landed typed accepted-config publication described by the canonical contract (accepted typed value plus actual revision published as one coherent cell before notification; module flips staged resources only after observing that same revision through a bounded cancellation-wakeable watch; no module-local revision counters, no `revision + 1`, no callback under the publication lock). The contract is landed: `AcceptedWatch<C>` (`sdk/src/config/accepted.rs`, coherent `read()` pair and cancellation-wakeable `wait_for_change`), `Registry::accepted_watch` (`sdk/src/registry.rs`) and `FactoryContext::accepted_watch` (`app/src/host.rs`), obtained in `register_module_observed` as `KeybindingsFactory` does. No candidate effects before acceptance, no native work under accepted publication lock. Rejection keeps runtime/publication/authority unchanged. Accepted updates preserve compatible user layout/ratios/floating/focus; structural policy is defined by 06. Physical writes after acceptance can fail/partially apply and cannot roll back transactionally: publish typed actual outcomes without pretending configuration rejection undoes them.
- Internal operation outcome has Enqueued, Applied, Partial, Uncertain plus typed failed/not-attempted/stale reasons and per-target/component evidence. Enqueued means actor admission only; Applied requires confirmation of stated scope, not all unrelated desktop windows. Reuse actual-send permits from 03, plan deadlines and current authority for every native component.
- Stop linearizes atomic seal/invalidation before any stalled commit wait; publish unavailable/tombstone immediately. Cancel/wake admission, enumeration, timers and all host handler waits before IPC joins. Drain outstanding frame/animation issuance (08 extends same seam), then 06-owned restore/unhide, then native observer removal/owner cleanup, actor close and worker joins off-main. Registry may already cancel before stop; cleanup uses fresh finite 2 s per-hop waits, not the cancelled work token.
- Preserve owner dispatch until reverse registry stop and factory finish/drain. In-flight native calls are irreversible; finite acknowledgement timeout is not a hard OS interruption guarantee or global shutdown SLA. Failed stage cleanup retains inert exact resources/progress/error state in quarantine, no restart until cleaned; retries do not duplicate already completed stages. No detached worker used to hide blocked joins.
- Host read-only status overlays ConfigStore held parse/type/I/O/deletion diagnostics without disk access; repaired file clears it independently of operation/native cleanup errors. Independent modules continue if Tiling fails/stops. Production registration remains gated until workspace-safe 06, not enabled early to demonstrate frames.
