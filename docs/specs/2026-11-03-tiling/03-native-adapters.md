# 03 — Safe native ownership and compile gates

Read when implementing after 02 and separate approval. Compile/fake proof is mandatory before runtime wiring; native execution needs fresh per-run approval.

## Scope

Extend landed `src/crates/macos/src/applications.rs`/tests additively; add focused `macos/src/windows/` AX observation/query/action, identity, displays/coordinates and tabs adapters, exports and fake support. Reuse landed frontmost watch and display pieces (`stache_macos::desktop::{DisplayFrame, DisplayEntry, DisplaySnapshot}`, where `DisplayFrame` is width/height only; `applications/display.rs` `ScreenRecord`, `appkit_rect_from_cg`, `select_display`), and consume landed `ApplicationObservation::activate_exact` (`applications/activation.rs`) for focus/raise and unhide-then-focus; never add a second activation path. Not yet landed, so this part adds them additively: application hide/unhide, terminate/hide/show notification observers, AXObserver, AX set-attribute, `_AXUIElementGetWindow`, SkyLight, display origin/visible frame/refresh/name and a display reconfiguration observer. This part owns application hide/unhide outright (part 06 uses it). SDK holds only safe values/traits where genuinely shared; Tiling `src/backend.rs` uses safe handles. See inventory native/identity/events rows. No module-local FFI or production registration.

## Requirements

- Applications retain current opaque `ApplicationId`, exact `NSRunningApplication` equality and host executor ownership. Never substitute PID, executable path, launch timestamp or bundle/name for authority. Preserve noTunes force-terminate API/tests; this part neither terminates nor launches apps. NSNotFound/unknown PID is diagnostic metadata, not identity fallback.
- Add owner-local opaque `WindowInstance` tokens: backend/service identity + runtime epoch + exact app instance + monotonically allocated AX instance token. Retain AX elements on their owner; revalidate app liveness, AX element equality/current membership and non-destroyed epoch immediately before action. CGWindowID remains query/display metadata/legacy CLI selector only. Destroy invalidates token before deferred work; same-app CG ID reuse cannot revive it. CLI resolves numeric IDs to current exact tokens before enqueueing.
- Define owner map explicitly: AppKit applications/NSScreen on main; AX observers, retained window elements and all AX queries/actions on a **dedicated AX owner thread** (one per consuming module). Main runs only AppKit presentation work and must never execute an AX query, enumeration chunk or action, so a hung application cannot freeze the Bar, HUD, tray or menus. MenuAnywhere and Tiling each own a **separate** AX owner with a distinct thread name (MenuAnywhere keeps `stache-ax-owner`); they share adapter code, never one serialized AX thread. Architecture decision: this part moves the shared AX FFI (`AxApi`, `AxElement`, `AxError`, `SystemAx`) from `macos/src/menu/ax.rs` into a neutral `stache_macos::ax` module; `menu` re-exports the existing names so MenuAnywhere callers stay unchanged. Moving a full traversal to main is not an approved fallback. Bounded marshalling is compile-proven with the real framework types; no moving retained objects by unsafe Send/Sync or integer-cast pointers, and no main→worker→main wait. Planned engineering defaults (not user config): AX messaging timeout 0.5 s per query element and 1 s per setting/action call, reusing the existing `ELEMENT_TIMEOUT`/`PRESS_TIMEOUT` constants rather than new ones; initial enumeration chunks at most 64 elements **and at most 50 ms of issuing time** before yielding/reposting, so one hung app cannot accumulate a long main/owner stall. Check remaining operation deadline/cancellation between elements and calls; no forced preemption or hard wall-time guarantee for an in-flight call.
- Callbacks enqueue IDs/refresh hints only, no title/frame walks, policy/effects/waits. Audit bounded nonpanicking callback paths. Panic containment is possible only in unwind-enabled builds; retained release `Cargo.toml:50–54` (`[profile.release]`, `panic = "abort"` at line 54) uses panic=abort and cannot recover arbitrary Rust panics. A fake unwind recovery test is not release recovery evidence. Native identity interning is minimal owner bookkeeping. Deferred queries recheck epochs and accepted authority; install observation before initial enumeration and reconcile overlap. Missing AX attributes are explicit unknown/unsupported, never zero frames/full success.
- Safe query/action contracts cover frame read/write (position and size separately), focus/raise through landed `ApplicationObservation::activate_exact`, hidden state, app hide/unhide owned here, minimized/fullscreen, title/subrole/resizability/minimums, display topology/frame/visible-frame/scale/refresh, app lifecycle and tab attributes. Return typed no-send/issued/partial/unknown outcomes with native status and actual observed geometry when available. No action implied by query/adaptor construction.
- Public APIs first. Inventory private `_AXUIElementGetWindow`, SkyLight window query/update/transaction calls individually; document missing public equivalent and minimum need before using. Add `_AXUIElementGetWindow` only via runtime symbol lookup; if absent, disable the CGWindowID capability honestly. SkyLight calls are inventoried but not added in 01–04 (no consumer there). Availability/symbol/version failures disable only affected capability honestly. Compile-proof private AX tab extraction (`AXTabGroup`/`AXTabs`, CF type checks/retain-release), IDs and fallback; do not assert tabs supported merely because constants compile. Part 08 owns runtime tab policy.
- Use the existing `ACKNOWLEDGEMENT_BUDGET` (2 s per-hop acknowledgement cap) and `CANCELLATION_QUANTUM` (10 ms cancellation observation quantum) from `applications.rs`, not new constants, sharing remaining command deadline below socket budget, not multiplying independent hop budgets. Main executes inline without waiting. Allocate duration timers only while work is active. Immediate atomic invalidation is independent of any stalled gate; actual issuance checks accepted config/revision, live generation, token, deadline and plan sequence. Narrow guard runs immediate native send only; no arbitrary module closure/dispatch/preflight/wait under gate. Already-issued effects cannot be undone; timeout after issue is Uncertain, never definitely not applied.
- Cleanup acknowledges owner removal; dispatch failure/timeout retains inert owner-thread-safe maps/leases for exact retry. Old cleanup cannot touch a successor. Quarantined adapters cannot install a new runtime before outstanding cleanup completes.

## Acceptance criteria

- [ ] TI-03-01: Real framework types compile with owner confinement, a dedicated AX owner thread per consumer (never main traversal, never a shared serialized AX thread with MenuAnywhere) and exact app/window tokens; same-app reused IDs/stale/cross-service/epoch targets cannot issue actions.
- [ ] TI-03-02: Typed public/justified-private query/write/tab/display seams compile; unavailable attributes/symbols/partial AX writes remain explicit and preserve existing applications callers.
- [ ] TI-03-03: Actual-send barriers prove immediate invalidation, deadline abandonment and truthful issued/uncertain outcomes; callback purity, bounded hops and no main wait cycle pass.
- [ ] TI-03-04: Failed install/removal resources stay inert/owned and retry exactly once; compile/native feasibility records distinguish proven from unverified capabilities.

## Tests, rollback and docs

Fake owner queues/barriers/clocks verify 0.5 s query/1 s action limits, 2 s hop/10 ms cancellation, enumeration yields at<=64 elements, pre-issue expiry versus in-flight overrun, no idle duration timers and bounded resource exhaustion. Also duplicate CG IDs within same app, app/PID replacement, two controls/registries, destroy/recreate, delayed callbacks, lost acknowledgements, malformed CF values, partial position/size, rejected dispatch, stalled native send, permission loss and cleanup retry. Unwind-only panic tests are labelled as such; separately audit release callback paths. Compile-only real linkage plus rustdoc; no AX queries/taps or desktop effects by default. [Validation](validation.md) controls manual gate scope.

Rollback removes only unconsumed adapters; retain existing applications API/consumers. Gate failure blocks later parts instead of weakening identity or moving FFI into modules. Update `architecture/{overview,sdk}.md`, testing and feature capability-limit docs for actually landed adapters only.
